# 实验协议

## 首轮开发实验 v0.1

数据划分沿用公开 FB train / dev_seen / test_seen。train=8500、dev_seen=500、test_seen=1000。试验样本按 SHA256(memeguard-pilot-v1:ID) 排序选择，不按标签或预测结果筛选：16 条训练记录、128 条开发记录。测试集图片和预测不进入开发流程。

先检查 144 张图片 SHA256 与解码、样本 ID 和图文对跨划分重复。相同图片配不同文案可能是有效对比样本，不能简单按图片去重。当前审计仅覆盖首轮子集；正式训练前还需全量重复和近重复检查。

基线固定提示词、最大图像像素 100352、最大输入 768 tokens、NF4 双重量化、阈值 0.5。分数是模型在标签 0/1 两个 token 之间的条件概率，未经过概率校准。主指标 AUROC，辅以 AUPRC、F1、精确率、召回率及混淆矩阵；仅报告开发集结果。

容量测试使用两条训练记录、两步 AdamW，LoRA rank=8 / alpha=16，q_proj/v_proj，视觉输入仍由原模型编码。它与原论文 rank=64 / alpha=128 及联合损失存在差异，目的仅为验证 8GB 显存下的反向传播和适配器更新。

## 后续完整实验

1. 在训练集上确定可承受的 SFT 配置，固定预算并保存检查点、训练曲线和失败日志。
2. 使用开发集比较零样本、SFT、SFT+训练集检索；检索库仅包含训练样本，不将验证和测试标签作为上下文。
3. 增加图像单模态、文本单模态和错配图文消融，检查是否真正利用图文关系。
4. 对照误报/漏报、讽刺与隐含攻击案例；独立报告英文数据到中文商品场景的迁移限制。
5. 完成模型与阈值选择后，才运行一次预先约定的独立测试；完整记录样本数、随机种子、置信区间和资源消耗。

首轮不足以声称完成训练、超过参考论文或达到线上可用标准。

## 第二轮固定训练协议（2026-10-24）

configs/sft-v1.json 固定 1024 条训练样本、1 epoch、128 次优化器更新，顺序仅使用 seed=17 打乱；按首轮同一 ID 哈希规则扩展，不按标签或模型表现选样。图文输入参与前向，仅 assistant 回答参与语言模型损失。视觉编码器冻结，语言模型 q_proj/v_proj 添加 LoRA；NF4、BF16、非重入梯度检查点；AdamW、5% warmup 后线性衰减、梯度裁剪 1.0。

扩充样本完成解码及跨划分相同图文对审计后才训练；64/128 步保存检查点。最终适配器与首轮相同 128 条开发样本、相同提示词、相同 0.5 阈值比较，不选择最优开发检查点、不修改独立测试。单种子开发实验不能代表全部 8500 条训练或独立测试效果。

## 固定阈值的额外验证（2026-10-24）

完整 SFT 在 0.5 阈值下出现显著的召回下降。仅用原 128 条开发记录，为两个模型分别选择满足召回至少 90% 且正常样本误报最少的阈值；若误报相同取最高阈值。阈值选择结果固定在 configs/thresholds-v1.json，记录输入预测文件摘要。

再获取 dev_seen 中排除原 128 条 ID 的全部 372 条记录；在全部 1024 条训练与 500 条开发记录之间检查相同图文对泄漏，检查通过后才评估。两个冻结模型均报告 0.5 与各自冻结阈值下的结果，不在这 372 条样本上重新选择阈值。这是额外验证，不是官方 test_seen。单次训练、英文数据和近重复未审计仍构成限制。

原 128 条开发预测进行 1000 次配对分层 bootstrap，给出 AUROC 差值的 95% 百分位区间；它仅描述这批样本的不确定性，不能替代多次训练和独立测试。
